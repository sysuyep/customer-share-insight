## 1. 阶段 1 分析初稿怎么写

先判断材料类型：

| 类型 | 特点 | 处理 |
|---|---|---|
| 客户故事访谈 | 专门为分享采集，有发展历程和关键转折 | 按 SKILL.md 的 11 项完整整理 |
| 教练入企对谈 | 围绕当下的经营问题，往往没有成长史 | 从当前处境、判断、问题、动作和变化搭建，缺的历史写"原文未覆盖" |
| 访谈笔记 | 二手整理，原话少 | 标明哪些是原话、哪些是整理者的转述 |

写法要点：

- **公开范围**用三档标记：✓ 可以上台讲；⚠ 确认后再讲；✗ 只放内部报告或不用。敏感数字、合伙纠纷、个人财务、家庭细节默认放在 ⚠ 或 ✗。
- **关键决定**按"处境 → 判断 → 动作 → 结果"写，哪一环原文没有就写"原文未说明"。这能提醒用户补访，也避免后面在页面上编造动机。
- **客户原话**轻度整理口语即可，注明"正式使用前请本人确认"。
- **待核实问题**单独列一张表：

| 原文写法 | 可能的意思 | 需要确认什么 |
|---|---|---|
| 转写里的地名、公司名 | 推测的正确写法 | 是否就是这个地方或公司 |
| 一组历年营收 | 是否同一种货币 | 货币、年份、是否含税 |
| 员工人数的两种说法 | 直接员工或含外包 | 上屏统一用哪个数 |

- **素材缺口**逐项列出，后面在页面上留占位，不要悄悄省略。

结尾的确认问题示例：

> 这是阶段 1 的分析初稿。请您确认：① 事实和数字是否准确；② 公开范围是否同意，有没有要删掉的经历；③ 分享场合、时长、语言和最终要哪些文件。确认后我再给出三个分享方向。

## 2. 从访谈里找素材

读访谈时，在分享人的话里找四类东西：

- **亮点**：讲的时候带着自豪的事，"我们做对了这件事"。
- **转变**："以前我们这样做，后来发现不行，于是改成那样"。
- **痛点**：至今还在头疼、还没想清楚的事。
- **改善**：最近正在试的新做法。

这四类素材分布在两个方面：

- **经营**：产品、客户、模式、定价、增长、品牌、渠道。
- **管理**：团队、文化、流程、决策、人才、组织、老板自己。

先把素材按"四类 × 两方面"摊开，再决定怎么切模块。先看素材再定结构，不要先想好结构再去找素材。

## 3. 切分模块的六种方法

没有标准答案，同一份材料用不同切法都能成立。阶段 2 的三个方向最好用三种不同的切法，让用户真正有得选。

| 切法 | 适合什么材料 | 模块标题示例（均为虚构） |
|---|---|---|
| 做对的几件事 | 分享人有几个清晰的自豪点 | "把一款产品做成顾客记得住的理由" |
| 关键转折 | 经历里有几个明显的转折点 | "从三个人一辆车，到十家门店" |
| 卡在哪几个坎 | 教练对谈、问题导向的材料 | "口碑很好，利润却上不去" |
| 回答了什么问题 | 分享人善于把经验讲成道理 | "扩张了，品质怎么不走样" |
| 给同行的忠告 | 分享时间短、分享人风格直接 | "先确定能做好，再去做大" |
| 走过的弯路 | 分享人愿意讲失败和反思 | "我们为什么放弃了代理模式" |

**时间线不做整套的主线。** 看到访谈里有年份，最容易按"那年做了什么"排成流水账，听众听完不知道这家企业为什么能从小做到大。时间只能用在某个模块内部，用来区分不同阶段的不同做法，例如"1–5 家店老板亲自盯；5–10 家店退出一线建后台；10 家以后靠系统"，这是用规模阶段讲做法，不是记流水账。

## 4. 模块怎么定义

每个模块写清以下几项：

| 项目 | 说明 |
|---|---|
| 内部领域 | 只用于规划，不出现在页面上，如"客户价值""内部运营" |
| 展示标题 | 页面上看到的标题，从分享人的话里提炼成一句有判断、有画面的话 |
| 模块核心 | 这个模块让听众明白什么，一句话 |
| 内容边界 | 哪些素材属于这里 |
| 不放入 | 相近但应该放在别的模块的素材 |
| 与下一个模块的关系 | 为什么下一个模块接在这里，如"找到市场之后，客户为什么选我们" |

常见的边界问题：对客户做的事（交付、服务、协同）和公司内部的管理（数据、目标、考核）混在一个模块里。两者要分开，或者明确说明先讲哪个、为什么。

## 5. 模块内部怎么组织页面

切法决定整套分几个模块；下面五种方式决定一个模块内部的页面顺序。按模块的核心观点挑一种：

- **分阶段的做法**：模块内按规模或阶段讲不同做法，每段讲清这个阶段的关键难题和对应动作。
- **几个并列的做法**：模块内拆成 3–4 个独立动作，每个都有名字和具体做法。
- **由外到内**：外部市场 → 内部团队 → 老板自己的变化 → 用什么机制固定下来。
- **从方向到执行**：方向选择 → 让团队想到一起 → 具体管理动作 → 结果。
- **完整循环**：客户价值 → 内部能力 → 组织机制 → 复盘改进。

不论用哪种，模块里都要有一页讲"我们具体怎么做"。

## 6. 每个模块写完的自查

| 自查 | 问自己 |
|---|---|
| 观点 | 这个模块的核心判断能不能用一句话说出来？ |
| 做法 | 有没有 2–4 个具体动作支撑？动作有没有名字？ |
| 细节 | 有没有人、数字、做法、原话？还是停在"加强管理""提升效率"这种空话？ |
| 场景 | 整套分享至少有 1–2 处具体场景：一个瞬间、一段对话、一个人的反应 |
| 承接 | 讲完之后能自然引到下一个模块吗？ |

任何一项答不上，就回去补。素材多且重要的模块 5–7 页，素材少的 3–4 页；素材只够 2 页，要么并到别的模块，要么在阶段 1 标出"这部分没问透"。最忌讳用空话把一个模块撑满。

**缺少"我们怎么做"的例子（虚构）**：

```text
模块：口碑很好，利润却上不去
  过渡页：好口碑为什么没变成好利润？
  观点页：市场有几百亿，我们只做到几千万
  因果页：口碑好 → 复购高 → 但仍在拼价格 → 因为没有集中到一个客群
  对比页：参考同行先把一个区域做透的做法
  金句页：要把口碑变成别人抢不走的东西
```

整段只有诊断和参考，没有一页讲分享人自己做了什么。补上：

```text
  做法页：
    ① 停掉三成的免费附加服务，把人手集中到最赚钱的客群
    ② 把响应时间从 7 天缩到 48 小时，作为对外的主要卖点
    ③ 给销售配技术同事一起见客户，不只报价
  结果页：客单价提升 35%，复购率从六成升到接近八成
```

## 7. 把经历提炼成别人能学的做法

企业家分享的价值不只是"我做了什么"，而是"我为什么这样做，你也可以这样试"。每个模块至少提炼一个可以被别的老板学去的做法：

| 原话 | 提炼成的做法 |
|---|---|
| "我们花了一年才开第一家店" | 确定能做好，才去开店 |
| "门店越多，我越要亲自去站一天" | 每开一家新店，管理层先走一遍流程 |
| "宁可走掉一半人，也不留不认同的" | 先保住对的人，再谈规模 |

好的做法命名：

- 八个字左右，方便分享人口头复述、听众记住。
- 有反面：隐含一个常见但不对的做法。
- 有适用范围：说明在什么阶段、什么行业有效。

提炼出的做法可以用在模块过渡页的副标题、"我们怎么做"页的卡片标题，以及模块最后的小结里。

## 8. 打动人的细节

只有方法的分享像管理课件。每份分享需要 1–2 个打动人的具体瞬间：有人物、有动作、有情绪。虚构的例子：

- 第一批货出了问题，老板带着两个员工连夜到客户仓库一件件返工，客户第二天又下了一张单。
- 一位跟了十年的老员工拿到新房钥匙，在群里发了张照片，老板说那是自己那一年最高兴的一天。

它和金句不同：金句是一句压缩过的判断，适合放在模块开场或收尾；细节是一个完整的场景，适合放在模块结尾或整场分享的倒数第二页。整页的场景不超过 1–2 页，太多会变成回忆录。

## 9. 博商暗线

原文提到博商、课程、老师、教练、同学、陪跑等内容时，作为分享人变化的一条线索，自然放进经营动作里。

可以出现的位置：

- 遇到瓶颈、需要外部视角时。
- 认知转折时，被某个问题、某堂课触发。
- 把学到的方法变成自己公司的做法时。
- 把外部方法变成内部机制时。

规则：

- 讲清"原来的问题 → 哪个启发 → 改了什么 → 有什么变化"。
- 删除检验：把课程和老师的提及全部删掉，故事仍然完整。删掉后变成残缺片段，说明是硬塞的。
- 不用一整页"我的学习心得"做植入，不写广告口号，不把经营结果全部归功于一次学习。
- 原文没提到就不编；可以在阶段 3 建议"这一页适合补问一个学习触点"。
- 只在确实使用了的页面标注"博商暗线"。

## 10. 画像页能放什么

画像页是对外介绍，越克制越好。

可以放：公司名称、行业、地区、阶段、规模、业务定位、客户类型；分享人姓名、身份、职责；3–5 个关键数字；Logo、本人照片、公司或业务现场照片的位置。

不能放：内部分析标签（如"决策风格""能力主题""性格判断"）、后面模块才展开的观点、需要解释的金句。这些放到后面的模块或洞察报告里。

公司画像、分享人介绍、关键数字合在一页里，不拆成两页，否则数字会出现两次。

## 11. 避免重复

同一个主题可以拆成几页，但每页要推进到不同层次：

- 有效：外部压力 → 内部能力的限制 → 老板意识到什么 → 新的做法。
- 无效：别人跟不上 → 团队跟不上 → 合伙人跟不上 → 大家都跟不上。

每页没有带来新的层次或新的后果，就是同一个意思在重复。同一个数字只在一页出现，下一页继续讲时要推进到新的问题，比如从"效率提高了多少"推进到"这对客户总成本和公司收益意味着什么"。

## 12. 阶段 2 的输出格式

每个方向先用一句普通文字说明特点，再把内容放进一个完整的 markdown 代码块。同一个方向的所有模块都在同一个代码块里，不要前半在代码块里、后半变成普通文字。

```markdown
## 方向 A · [主标题]

**副标题**：[一句话]
**切法**：[六种切法之一]
**主线**：[一句话说清整场分享讲什么]
**适合**：[什么听众、什么场合]

- **模块 1 · [展示标题]**
  - 模块核心：……
  - 内容边界：……
  - 不放入：……
  - 与下一个模块的关系：……
- **模块 2 · [展示标题]**
  - ……

**结尾落点**：[用什么收尾，一句话]
```

三个方向都写完后，问用户："请选择一个方向，或者告诉我想把哪几个模块融合起来，我再写逐页框架。"
