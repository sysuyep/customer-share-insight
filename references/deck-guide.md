## 1. 模板怎么用

以 `assets/deck-template.html` 为起点，不要从零写。模板已经处理好画布缩放、键盘跳页、打印分页、浅色和深色两套配色。

1. 复制模板，改名为 `{customer}_{topic}_deck.html`。
2. 按逐页框架保留需要的版式，删掉不用的；同一种版式可以复制多次。
3. 替换全部示例文字。模板里的示例公司是虚构的，带"【示例】"的地方必须改掉，校验脚本会检查。
4. 按样稿阶段定下的强调色，修改 `:root` 里的 `--accent`、`--accent-strong`、`--accent-soft`，以及深色模式和打印部分对应的值。
5. 每页保留结构 `.deck > .slide-wrapper > section.slide`，`section` 上保留 `class="slide 版式名"`、`data-page="页码"`、`data-role="版式名"`。
6. `.page-num` 写两位页码，和 `data-page` 一致。
7. 照片转成 base64 写进 `.photo` 的 `background-image`，保证单个文件就能打开；不引用网络上的字体、脚本、图片。

直接把 HTML 写进文件。如果要用脚本批量生成，必须真正运行脚本，把输出写进文件；文件里不能留下 `html += """`、`# SECTION` 这类脚本代码。

## 2. 内容关系对应哪种版式

先判断这一页的内容关系，再选版式。版式本身没有对错，只看它是否表达了这一页的关系。

| 内容关系 | 版式（data-role） | 什么时候用 |
|---|---|---|
| 开场 | `cover` | 第一页 |
| 介绍公司和分享人 | `portrait` | 第二页，公司、分享人、关键数字合在一页 |
| 告诉听众讲几部分 | `agenda` | 画像页之后，全场一页 |
| 开始新的一部分 | `module-opener` | 每个模块开头，大号编号加模块标题 |
| 一个强判断 | `big-claim` | 只有一个观点要被记住 |
| 原话本身有力量 | `quote-page` | 原话短、口语化、能代表转折或情绪 |
| 一个具体瞬间 | `scene` | 有人物、动作、对话或情绪的场景 |
| 改变前后 | `contrast` | 前后两种做法都能具体描述 |
| 两个维度交叉 | `matrix` | 两个维度共同决定选择 |
| 有先后顺序的动作 | `flow` | 3–5 步，每一步是动作 |
| 一环推一环 | `causal-chain` | 每一步都能回答"为什么导致下一步" |
| 基础、做法、结果 | `pyramid` | 三层之间有支撑关系 |
| 大目标逐层细分 | `breakdown` | 年度拆到月、周、日；总目标拆到部门、个人 |
| 公司发展节点 | `timeline` | 3–5 个节点；原文没有年份写"年份待补充" |
| 用数字讲规模或变化 | `metrics` | 改变前后的大数字对比，或 3 个关键数字 |
| 我们具体怎么做 | `method-grid` | 模块里的做法页，4 个有名字的动作 |
| 为什么这样选 | `reason-cards` | 一个决定背后的 4 个理由 |
| 不同阶段不同做法 | `stage-method` | 按规模或阶段讲做法，不是记流水账 |
| 结束 | `closing` | 一句话落点和一句留言 |

照片页：在 `big-claim`、`scene`、`cover` 上加 `has-photo`，放入 `.photo` 和 `.shade` 两个层（模板第 21 页有示例）。

几条容易出错的地方：

- 拆解画成逐层细分（越往下越具体），不要画成逐层增长的台阶。
- 左右两栏只在两侧确实有关系时使用：改变前和改变后、问题和行动、场景和从中得出的判断。不要左边放一段原话、右边放几个标签。
- 编号只用在步骤、阶段、并列做法和导览上，内容之间没有顺序或并列关系时不编号。
- 整套至少用 5 种不同版式，避免每页都是"标题加三个并列块"。

## 3. 各版式的字数上限

画布是 1920×1080，超出的文字会被裁掉。下表是按模板字号算出的安全字数（中文字数，一个英文单词算一个字）。超过就拆成两页；字数不到上限一半的内容页，往往说明内容太薄，要么补细节，要么和相邻页合并。观点页、金句页、过渡页字少是正常的。

| 版式 | 总字数上限 | 各部分建议 |
|---|---|---|
| `cover` | 70 | 主标题 ≤ 25，副标题 ≤ 30，分享人和公司 ≤ 15 |
| `portrait` | 200 | 公司简介 ≤ 90，分享人 ≤ 30，4 个数字各 ≤ 15 |
| `agenda` | 220 | 每个模块：标题 ≤ 16，副标题 ≤ 25 |
| `module-opener` | 100 | 标题 ≤ 20，副标题 ≤ 30，原话 ≤ 40 |
| `big-claim` | 150 | 主张 ≤ 32，支撑句 ≤ 70，事实 ≤ 35 |
| `quote-page` | 70 | 原话 ≤ 45，补充一句 ≤ 30 |
| `scene` | 220 | 标题 ≤ 20，场景叙述 ≤ 130，判断 ≤ 45 |
| `contrast` | 160 | 标题 ≤ 25，每侧：小标题 ≤ 16，说明 ≤ 45 |
| `matrix` | 160 | 标题 ≤ 30，每格：名称 ≤ 8，说明 ≤ 18 |
| `flow` | 180 | 标题 ≤ 25，每步：名称 ≤ 6，说明 ≤ 25 |
| `causal-chain` | 180 | 标题 ≤ 25，每环：名称 ≤ 10，说明 ≤ 18，结论 ≤ 25 |
| `pyramid` | 140 | 标题 ≤ 25，每层说明 ≤ 30 |
| `breakdown` | 160 | 标题 ≤ 30，每层 ≤ 28 |
| `timeline` | 180 | 标题 ≤ 25，每个节点：名称 ≤ 8，说明 ≤ 22 |
| `metrics` | 120 | 标题 ≤ 30，每个数字说明 ≤ 15，补充 ≤ 40 |
| `method-grid` | 260 | 标题 ≤ 25，每个做法：名称 ≤ 10，动作 ≤ 35，原话 ≤ 20 |
| `reason-cards` | 200 | 标题 ≤ 25，每个理由：名称 ≤ 6，说明 ≤ 20，底部一句 ≤ 35 |
| `stage-method` | 240 | 标题 ≤ 25，每个阶段：标签 ≤ 8，名称 ≤ 8，说明 ≤ 28 |
| `closing` | 100 | 标签 ≤ 12，主句 ≤ 25，留言 ≤ 40 |

## 4. 写页面时的规则

- **从上到下：标题 → 说明 → 图示。** 标题占满一行宽度，说明紧跟标题，下面才是矩阵、流程等图示。不要标题靠左、说明放在右侧小字。
- **字号不低于模板。** 模板里的字号已按会场距离定好（正文 24–34px），不要为了塞下更多字而改小，字多就拆页。
- **底部留空。** 正文不进入画面最下方 140px，那里只放页码。
- **空间多就放大。** 某页字少、留白多时，把字号调大或改用更合适的版式，不要留一大片空白、文字挤在一角。
- **标题手动换行。** 中文标题在语义处用 `<br>` 换行，不要让浏览器在词中间断开（如"味/道"），也不要让一两个字单独成行。不能拆开的词组用 `<span class="nb">` 包起来。
- **数字。** 大数字和单位分开写：`<div class="metric-value">320<small>人</small></div>`。同一个数字全篇只在一页出现。
- **缺素材。** 用 `<div class="placeholder">待补：具体内容</div>` 占位，写清楚需要什么照片。
- **讲稿同步。** 页面定稿后，按逐页框架里的"讲稿要点"写讲稿，页码一一对应。

## 5. 交付前检查

依次运行（`<SKILL_DIR>` 换成本 Skill 所在路径）：

```bash
python3 <SKILL_DIR>/scripts/validate_html_deck.py deck.html --speaker 分享人称呼
python3 <SKILL_DIR>/scripts/check_deck_render.py deck.html --screenshots shots/
python3 <SKILL_DIR>/scripts/validate_speaker_notes.py speaker_notes.md --deck deck.html --speaker 分享人称呼
python3 <SKILL_DIR>/scripts/validate_insight_report.py insight_report.html
```

- `validate_html_deck.py` 检查结构、版式、外链、禁用的视觉写法，并打印标题连读、重复数字和常见 AI 腔。
- `check_deck_render.py` 在无界面浏览器里打开演示稿，逐页检查文字溢出、正文进入底部区域、字号过小、标题单字掉行，并逐页截图。需要 Python 版 Playwright；没有安装时会提示，改为在浏览器里人工翻一遍。
- 截图看一遍：页面之间是否连贯、有没有大片空白、照片是否压住文字。只看有问题的页，不要反复全量截图。

交付时在回复里给出三个文件的完整路径，说明运行了哪些检查、还有哪些没验证（例如没在投影仪上看过）。不要在对话里粘贴 HTML 源码。
