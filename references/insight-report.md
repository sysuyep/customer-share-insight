# 阶段 4：客户洞察报告

洞察报告给内部团队看，用来理解客户、设计后续服务。它不是分享稿，也不是演示稿内容的复制。交付物是单个 HTML 文件 `{customer}_{topic}_insight_report.html`，以 `assets/insight-report-template.html` 为起点。

## 结构：六章，固定顺序

先认识客户（画像、发展史）→ 再看客户怎么做生意（业务、理念）→ 然后诊断并给出服务建议 → 最后看已经发生的学习改变。

| 章 | 名称 | 写什么 |
|---|---|---|
| 抬头 | 客户洞察报告 · 公司名 · 客户姓名 | 材料来源、整理日期、标注说明；下方 3–4 个关键数字 |
| 1 | 客户画像 | 分层表：创始人个人、公司、组织状态三组，一级类目合并单元格，每组只出现一次 |
| 2 | 企业发展时间线 | 3–5 个节点，竖线加节点的时间轴样式；每个节点写做了什么、当时的瓶颈、怎么突破 |
| 3 | 核心业务与经营模式 | 收入结构、差异化、渠道、成本等，只写原文涉及的 |
| 4 | 管理理念与价值观 | 用人、信息、激励、决策、老板自己的位置等 |
| 5 | 诊断与机会 | 3–4 条诊断，每条是"挑战 → 判断 → 服务"一条完整思路 |
| 6 | 博商学习与已发生的改变 | 按经营维度分组：原来的问题、触发改变的课程或老师、现在的状态 |

不另加"客户原话""关键判断""风险提示""分享建议"等章节。原话作为证据放进诊断的挑战部分；风险和建议并入诊断的服务部分。

## 每章的标题写结论

每章有一个小标签写章节名（如"05 诊断与机会"），大标题直接写这一章的结论，读者只看标题就知道结果。例如：

- 客户画像 → "一位从学徒做起、重品质胜过重速度的创始人，带着一家正在从老板驱动转向标准驱动的工厂"
- 诊断与机会 → "第三座工厂能否复制品质，取决于能不能先培养出下一任厂长"

## 画像表的规则

- 个人画像只写人的信息，公司画像只写企业的信息，不混写。
- 原文没有的写"原文未覆盖"；根据原文归纳的在"依据"列写"推断"并简述理由。
- 数字写清单位和年份。

## 诊断的写法

每条诊断讲一个独立的经营问题，不要两条讲同一件事。

| 部分 | 内容 |
|---|---|
| 挑战 | 表层症状（客户每天看到什么）、深层问题（背后的原因）、影响（不解决会怎样）、证据（原话） |
| 判断 | 一个八字左右的名字、为什么能从挑战得出这个判断、适用范围 |
| 服务 | 我们能怎么帮、从哪里切入、客户内部可能的阻力、需要避免的说法、优先级（高 / 中 / 低） |

服务建议要能从判断推出来，不写和前面无关的推荐。

## 学习改变的写法

- 按维度分组：战略、商业模式、团队、领导力、财务、营销、组织、文化中原文真实涉及的几个。
- 每个维度三项：原来的问题、触发改变的课程或老师（写具体名称，原文没说就注明）、现在的状态。
- 不按时间列课程清单，不把经营结果全部归功于学习。
- 原文几乎没有学习记录时，写"原文未覆盖学习记录"，不要编。

## 视觉要求

模板已经按这些要求做好，替换内容时保持：

- 灰白中性底色加一个强调色；章节之间用底色交替区分，不用阴影卡片和左侧彩色边条。
- 标题用宋体类字体（分析报告可用），正文用黑体，数字用等宽数字。
- 关键数字大字号，单位小一号、颜色浅一档。
- 名词解释、推断说明放在每章末尾的"说明与依据"里，默认收起。
- 手机宽度（390px）下整页不能左右滑动，宽表格在自己的区域里滑动。
- 跟随系统切换深色模式；打印时固定浅色。
- 不引用网络上的字体、脚本、图片。

## 交付前检查

运行 `python3 <SKILL_DIR>/scripts/validate_insight_report.py insight_report.html`，再人工确认：

- 六章齐全、顺序正确，没有自加章节。
- 每章标题是结论，不是章节名。
- 画像表个人、公司、组织三组分开，未知信息有标注。
- 每条诊断的挑战、判断、服务都齐全，而且前后能推得通。
